# 技术说明

本文记录实现细节与设计取舍，便于二次开发。

## 整体架构

单文件实现（`src/ts2mp4.py`，约 1700 行），Tkinter GUI + 后台线程处理。

```
GUI 主线程                    worker 线程                ffmpeg 子进程
────────────                 ──────────                ─────────────
点击「开始转换」
  └─ 读取设置 → 起线程 ───→ 逐个调用 convert_one ──────→ Popen(ffmpeg)
                              │                                │
                              │                          读线程 → Queue
                              │                                │
                     消费 Queue 事件 ◄─────────────────────────┘
                       更新进度条
```

### 事件协议

worker 与 GUI 通过 `queue.Queue` 通信，事件类型前缀区分用途：

| 前缀 | 用途 | 载荷 |
|---|---|---|
| `prog` | 转码进度 | (已处理秒, 百分比, 剩余秒) |
| `done` | 转码成功 | (文件名, 字节数) |
| `err` | 转码失败 | (原因文本) |
| `log` | ffmpeg 输出行 | (文本) |
| `tsprog/tsdone/tserr/tslog` | TS 无损拼接 | 同上 |
| `mprog/mdone/merr/mlog` | 多文件合并 | 同上 |
| `slog/spart` | 超大文件分段 | (说明) / (文件名, 大小) |

**关键约定**：消费端只认 `done`/`err` 决定成败，进度事件仅用于刷新 UI。
早期版本用进度百分比作为循环退出条件，因为进度封顶 99%（100% 留给完成态），
会在 `done` 入队前提前退出，导致成功任务被误记为失败。

## 核心设计

### 1. 自然排序

录制分片常见 `ch1.ts`…`ch10.ts`，字符串排序会把 `ch10` 排到 `ch2` 前面，
导致合并顺序错乱。

```python
_NAT_RE = re.compile(r"(\d+)")
def natural_key(path):
    name = os.path.basename(path)
    key = []
    for p in _NAT_RE.split(name):
        if p.isdigit():
            key.append((1, int(p), ""))      # 数字段按数值比较
        else:
            key.append((0, 0, p.lower()))    # 文本段按字典序
    return key
```

### 2. 三重超时保护

`convert_one` 直接迭代 ffmpeg 的 stdout 时，进程若不退出就会永久阻塞，
整个队列锁死。Windows 上 `select` 不支持管道文件对象，无法用 select 绕开，
因此采用**读线程 + Queue**：

```python
line_q = queue.Queue(maxsize=1000)
def _reader():
    try:
        for ln in proc.stdout:
            line_q.put_nowait(ln)     # 队列满则丢弃，主循环只关心进度/错误
    finally:
        line_q.put(("__EOF__", None))
threading.Thread(target=_reader, daemon=True).start()

while True:
    if cancel_flag():            # 用户点了「停止」
        ...
    if elapsed > total_limit:    # 总时长上限（最长 1 小时）
        ...
    if idle > stall_limit:       # 90 秒无任何输出 = 卡死
        ...
    line = line_q.get(timeout=0.3)   # 超时即 continue，不阻塞
```

超时阈值：

| 保护 | 阈值 | 作用 |
|---|---|---|
| 用户中断 | 即时 | 点「停止」立刻终止 ffmpeg |
| 无进展 | 90 秒 | 判定卡死，杀进程跳过该文件 |
| 总时长 | 最长 1 小时 | 兜底 |

验证方式：构造一个「永不输出且永不退出」的进程（`python -c "time.sleep(600)"`），
确认能在超时阈值内被准确中止。

### 3. 加密 HLS 支持

m3u8 下载的剧集，TS 分片是 AES-128 加密的，**单个文件无法解码**。

处理要点：
1. 找到本地清单（`local.m3u8` 优先于 `original.m3u8`）
2. **改写密钥 URI**：原清单里的路径是手机绝对路径（如
   `/storage/emulated/0/.../enc.key`），本地找不到，改为同目录的 `enc.key`
3. **加 `-allowed_extensions ALL`**：ffmpeg 默认拦截 `enc.key` 这类非媒体扩展名
4. 片段行改成本地文件名
5. 以改写后的清单为单一输入，由 ffmpeg 边解密边转码

```python
OUTPUT_FORMATS = {
    "mp4": {"ext": ".mp4", "faststart": ["-movflags", "+faststart"]},
    "mkv": {"ext": ".mkv", "faststart": []},   # MKV 无需 faststart
}
```

### 4. 合并的两种策略

**先合并 TS 再转码**（默认流程）：

```
N 个 TS  --concat demuxer -c copy-->  1 个临时 TS  --转码-->  1 个 MP4/MKV
            （无损，秒级）                        （只编码一次）
```

TS 是流式格式，拼接只是字节级连接，不损失画质。相比「逐个转再合并」，
编码次数从 N 次降到 1 次。

**合并兼容性判定**：

```python
def streams_compatible(infos):
    # 必须同时比对：视频编码、宽高、音频编码、采样率、声道
```

只比编码名是不够的 —— 分辨率不同时 `-c copy` 会导致画面尺寸错乱，
必须回退到 concat filter 重编码对齐。

### 5. 4GB 自动分段

MP4 容器单文件上限约 4GB，超出后播放器打不开。
MKV 没有此限制（Matroska 支持到 2^63），因此 MKV 直接跳过分段。

段长必须**由码率反推**，不能用固定分钟数：

```python
bytes_per_sec = size / dur
seg_sec = (max_bytes * 0.85) / bytes_per_sec    # 留 15% 余量给封装开销
seg_sec = min(seg_sec, target_minutes * 60)
n = int(dur // seg_sec) + 1
```

例：3.89GB / 137.5 分钟 → 每段 100 分钟 → 2 段（2.97GB + 0.93GB）。

### 6. 输出格式差异

| | MP4 | MKV |
|---|---|---|
| 4GB 限制 | 有 | 无 |
| copy 模式 | 需 `-bsf:a aac_adtstoasc`（ADTS→ASC） | 不需要 |
| faststart | 需要 | 不需要 |

`aac_adtstoasc` 是 MP4 专用 filter，MKV 可直接承载 TS 里的 AAC。

## 已知限制

- **仅 Windows**：路径处理、快捷方式、窗口样式均按 Windows 设计
- **无 ffprobe**：静态 ffmpeg 包不含 ffprobe，时长探测退回解析 `ffmpeg -i` 的
  `Duration:` 字段
- **加密 HLS 需整个文件夹**：单独拖一个加密分片无法处理
- **HLS 直播流**：只处理 VOD 清单，不支持边录边转

## 性能参考

137 分钟 1080p 加密剧集（212 个分片，1920×1038 H.264 + AAC）：

| 方式 | 耗时 | 体积 |
|---|---|---|
| 重编码 MP4（medium） | 90 分钟 | 2.4 GB |
| 重编码 MP4（veryfast, crf23） | 约 55 分钟 | 2.5 GB |
| 换封装 MKV | **1.4 秒** | 与源同码率 |
